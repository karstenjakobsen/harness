# Phase 2 prerequisite — separate attempt preparation from worker execution

An owner can prepare and inspect a worker assignment on a machine with neither Docker nor Nomad available. Preparing the attempt gives us an ID we can use later, even if we never launch anything.

- [x] Retire `operator work start` and remove its production `DockerWorkerLauncher` dispatch and recovery path. Check all launcher callers, including `operator work show` in [the Click adapter](../../packages/harness_operator/src/harness_operator/commands/work.py). Make show read persisted work, attempt, call and artifact data through the public API. Runtime-only fields may be absent on externally run attempts.
- [x] Add the proposed owner command `operator work prepare WORK_ITEM_ID --attempt-id ID` as a thin wrapper around existing [WorkAPI](../../packages/harness_api/src/harness_api/models/work.py) attempt creation. Return JSON with the work item and attempt identifiers. Preparing twice returns the same attempt for the same work item. Reusing the ID for another item fails. Preparation must succeed offline, with no image, scheduler endpoint, scratch directory or Codex login.
- [x] Preserve the generic worker image, attempt-scoped worker MCP tools, skill reads, audit and saved-artifact retrieval. Expose the existing worker MCP app independently of the launcher's private server lifecycle. For manual file handoffs, give the trusted owner a way to bind the per-attempt scratch and issue/revoke the existing attempt credential separately from preparation. Keep credentials in a private runtime file and out of seed JSON and logs. The attempt ID is a lookup key.
- [x] Keep the Slice 9 cluster setup and backend proof callable in their existing development tests. Ensure no production CLI, HTTP, MCP or model operation can dispatch a worker. Retire tests that require the deleted launcher and retain tests for attempt authority, artifacts and audit. Update the command catalog, terminology, README and Make targets so none advertise the retired launch path.
- [x] Verify in an empty temporary workspace, through separate CLI processes, that create, prepare, repeated prepare and show succeed with Docker, Nomad and Codex unavailable. Check the saved goal revision, one attempt, and empty execution outcome. Check CLI discovery and direct invocation of the retired start command. Run and report `make check` and `make test`.

Complete this cut before using the [Slice 11 experiment](SLICE11.md). The local harness-initiated Docker handoffs had an unresolved host namespace failure at the Slice 10 baseline. Preserve that history when changing the live test targets.
