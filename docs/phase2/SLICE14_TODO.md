# Slice 14 — Run one work item with Codex and Kiro

Prove that Codex and Kiro can each deliver the [city assignment](cities.json) using an explicitly selected model, reasoning effort and provider API key. Seed one work item and prepare two fresh attempts against the same goal revision. The owner renders each Jinja job and submits it directly to Nomad. Harness prepares the attempts, serves worker MCP and retains the submitted files.

Keep worker images and their entrypoint in `dev/worker/`, experiment code, tests and published evidence in `dev/phase2/`, and private run data under `dev/.harness/`. [Phase 2 boundary](../../docs/phase2/phase2.md) · [Slice 13 acceptance](../../docs/phase2/SLICE13_TODO.md)

## First checkpoint — Kiro reads its assigned brief

- [ ] Build a pinned Kiro CLI in [Dockerfile.Kiro](../worker/Dockerfile.Kiro). It currently uses the Codex base image. Run it as the workload user with a fresh home, a Kiro API key and a private Harness attempt credential.
- [ ] From a manually submitted Nomad job, start headless Kiro with an explicit model and effort, configure the worker MCP endpoint with the attempt bearer token, and require MCP startup. Verify through `operator work show ATTEMPT_ID` that `get_work_brief()` returned for that attempt and grant. If run as a standalone probe, give it its own attempt ID and report it separately from the two delivery runs. [Kiro headless mode](https://kiro.dev/docs/cli/headless/) · [Kiro MCP configuration](https://kiro.dev/docs/mcp/configuration/)

## Worker and launch configuration

- [ ] Build each image with its own pinned CLI. Keep `harness-worker run --attempt-id ID` as the common entrypoint. Share the assignment prompt, workspace, attempt-ID check and MCP credential checks. Keep CLI arguments and MCP client configuration specific to each worker. Preserve the existing Codex build path used by `make worker-image` with a compatibility Dockerfile or symlink inside `dev/worker/`. [Codex image](../worker/Dockerfile.Codex) · [Worker entrypoint](../worker/harness-worker.py)
- [ ] Add `--worker codex|kiro`, `--model MODEL`, `--effort LEVEL` and `--auth api-key` to the [experiment renderer](experiment.py). Render the selected worker image by digest. Older invocations and receipts must still run with the existing Codex saved-login behavior. Record the worker, image digest, requested model, requested effort and auth mode in the receipt. Record the CLI version from the image and any effective settings the CLI actually reports.
- [ ] For Codex, pass `--model` and the `model_reasoning_effort` config override to `codex exec --json`. For Kiro, pass `--model` and `--effort` to `kiro-cli chat --v3 --no-interactive --output-format stream-json --require-mcp-startup`. Verify that the selected model supports the requested effort. Fail clearly on an unsupported pair. [Codex configuration](https://developers.openai.com/codex/config-reference) · [Kiro headless flags](https://kiro.dev/docs/cli/headless/)
- [ ] In API-key mode, stage only the selected provider key and the attempt credential in separate mode-0600 files on the private runtime mount. Set `CODEX_API_KEY` or `KIRO_API_KEY` for the selected CLI. Use `HARNESS_WORKER_TOKEN` for worker MCP. Fail on a missing provider key even when the host has a saved login. Keep secret values out of argv, rendered jobs, receipts, transcripts and published evidence. Revoke the grant and remove the staged credentials during cleanup. [Codex automation](https://developers.openai.com/codex/noninteractive) · [Kiro authentication](https://kiro.dev/docs/cli/authentication/)
- [ ] Cover two distinct supported model/effort selections per worker in focused offline tests. Check the invocation and environment passed to each CLI, missing-key and unsupported-pair failures, and credential handling using dummy secrets. Exercise the existing Codex saved-login invocation and legacy receipt.

## Live acceptance — two deliveries and two replays

- [ ] Seed the city work item once. Prepare a Codex attempt and a Kiro attempt with different attempt IDs, job IDs, scratch directories, grants and receipt directories in the same Harness workspace. For each delivery, render and inspect the job, then submit it directly to Nomad. Use API-key auth and a fresh home for each run. Expect one worker session per delivery and zero AI operator sessions.
- [ ] For each attempt, verify the MCP audit records a returned `get_work_brief`, a read of `worker-handoff@1` and a returned `submit_work_result` linked to that attempt’s artifact and grant. Record the observed Nomad exit separately. After scratch cleanup and grant revocation, export `cities.txt` with the owner CLI and check its exact UTF-8 bytes against the fixture. Verify the exported artifact ID against `operator work show ATTEMPT_ID`. Finish the first export before starting the second worker because `operator work artifact GOAL_ID` returns the goal’s latest artifact. Verify the goal retains its original revision and status.
- [ ] Extend the [activity reader](watch.py) and the runner’s session check for each CLI’s native event format. For each worker, display and save one substantive command or MCP event, then independently confirm the same Nomad task is still running. Drain stdout before allocation cleanup, keep stderr private, and replay the same event by attempt ID afterward. Check submission claims against the Harness audit and retain any partial capture with its status.
- [ ] Create and run `dev/phase2/SLICE14_EVIDENCE.sh`. Capture the manual commands, sanitized settings and live events, artifact IDs and hashes, and replay results in `dev/phase2/SLICE14_EVIDENCE.md`. Record `make check` and `make test` results and report the live worker results separately. Mark any unexecuted check and its blocker.
