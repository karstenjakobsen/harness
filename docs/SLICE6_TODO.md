# Slice 6 — Let an operator learn from earlier runs

Starting with only a goal ID, a fresh operator session can identify who changed the success criteria, compare the two revisions, and name the run and call that saved the change. The owner can then inspect which records that session consulted. The operator chooses when to consult history and how to interpret it. Subgoal creation, worker execution, automated retries and a separate learning store are outside this slice. [Slice 6 design](SLICE6.md)

## Implementation

The HTTP and CLI already share two owner-scoped `GoalAPI` queries. Expose those queries through MCP so a web client and an operator can follow the same references. [Activity contract](../README.md#operator-activity) · [Goal model](../packages/harness_api/src/harness_api/models/goals.py)

| Read-only MCP tool | Public model query and existing HTTP route | Facts the operator can use |
| --- | --- | --- |
| `get_goal_activity(goal_id)` | `GoalAPI.get_goal_activity` · `GET /goals/{goal_id}/history?view=activity` | Chronological revisions with their definitions and committing calls, observations with attribution, decisions with citations, and related calls across operators. |
| `get_run(run_id)` | `GoalAPI.get_run` · `GET /runs/{run_id}` | Run identity, registered operator and bound grant when present, ordered calls, requested targets, outcomes, returned references, and committed or retrieved changes. |

- [x] **Require a recorded run for both reads.** Expose both tools in advisory and delegated `operator ask` sessions through the existing run lifecycle. A standalone MCP server launched without a run ID omits both tools from discovery and rejects direct invocation. Apply the existing goal-read visibility in the public model queries, including when one operator inspects another's run. Derive the workspace owner and reading session from trusted context. Keep each write bound to its own action, target and active grant. [MCP server](../packages/harness_mcp/src/harness_mcp/server.py)
- [x] **Record the request and outcome.** Extend the existing MCP call recorder to persist the attempt before dispatch. Record the requested goal ID for an activity read and a distinct requested run ID for a run read. Link an activity read to the goal timeline when the goal resolves at call start. Save the outcome and references from the actual structured result together before handing the reply to the transport.
- [x] **Preserve what the reader saw.** For a timeline, record the revisions, observation IDs, decision IDs and citations, and call references exposed. For a run, save its ID and outcome along with each returned call's `(run_id, sequence)`, outcome, and commit or retrieval references for revisions and decisions. Capture those values from the response so later changes to the inspected run or call leave the saved read intact. Expose the saved references one level deep when inspecting an earlier history call. Distinguish an empty result from an unfinished or denied call. [Activity records](../packages/harness_api/src/harness_api/models/activity.py)
- [x] **Exclude the executing call from its own snapshot.** Pass the recorder's call reference to the shared query. The model checks that the call is unfinished and matches the tool and target before omitting it from the snapshot. Earlier calls remain visible, including unfinished ones. A subsequent read can see the completed history call and its saved references. The model rejects any attempt to save a history result containing its own call.
- [x] **Preserve attribution.** Use a revision's `committing_call` to identify who saved it, even if the reply was interrupted. Keep the original actor on each historical call. A returned observation records exposure, while a decision citation records use of evidence. When asked why a change was made and the history contains no rationale, the operator should say the reason was unrecorded.
- [x] **Upgrade storage and document the contract.** Extend the fresh schema and the populated v11 upgrade path for the tool names, run targets and returned references. Reopen the upgraded workspace and verify that earlier grants, call sequences, commit links and citations survive. Update the HTTP activity contract, MCP tool list and attribution terms.
