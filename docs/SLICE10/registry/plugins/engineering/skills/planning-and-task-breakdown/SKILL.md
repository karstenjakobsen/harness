# Planning and task breakdown

## Purpose

Turn a desired outcome into small pieces of work that can be reviewed independently. Use this skill when planning subgoals or writing a brief for a worker.

## How to plan

1. Read the current goal, its revision, and any related work. Note the facts and the questions that affect scope.
2. For each proposed piece, write the outcome and an observable acceptance criterion. Include the input, the expected result and how someone can verify it.
3. Identify prerequisites. Order work by dependencies and group changes needed to prove one complete behavior.
4. Give each worker brief a concrete deliverable, the inputs it needs and the boundary of the task. Pin any skill revisions the worker should use.
5. Ask the owner about a missing decision when guessing would change the outcome. Save definitions or delegate work only through the action authorized for the session.

## Example

For “generate legal chess moves,” one work item could request two Go test cases for king safety. Give the worker the board representation and ask for each starting position, candidate move, expected legality and a short explanation. The cases give the operator something to review and an engineer something to run against an implementation.
